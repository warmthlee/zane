# AI 协作模型

## 角色分工

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| 人（产品负责人） | 范围、优先级、产品判断、发布确认 | — |
| AI Agent | 实现、重构、文档草稿、验证执行 | 替代产品判断、擅自扩大范围 |
| 工程流程 | 质量门槛、验收、可维护性 | — |

## 契约文件

- 根目录 `AGENTS.md`：所有 Agent 的通用契约。
- 根目录 `CLAUDE.md`：Claude Code 专属入口。
- 子目录 `AGENTS.md`：覆盖所在子树，越近优先级越高。
- `docs/01-requirements/prd/`：每个功能域一份 PRD。
- `docs/08-governance/adr/`：每个架构决策一份 ADR。
- `docs/`：项目事实来源，优先于会话记录。

## 任务模板

每次任务开始前明确：

1. **目标**：要达成什么。
2. **范围**：做什么、不做什么。
3. **约束**：技术、产品、时间。
4. **验收标准**：可观察的完成条件。
5. **验证方式**：命令或手动检查步骤。

收尾时确认：

- 范围未扩张。
- 验证已执行并记录。
- 文档已同步。
- 遗留风险已登记。

可复用模板：`.claude/commands/plan-task.md`、`.claude/commands/verify-task.md`。

阶段 1 按步骤拆会话时使用 `.claude/commands/step.md`（`/step S1`）：一个会话只做一个步骤，状态、验收证据与交接摘要写回 [`../01-requirements/delivery-plan.md`](../01-requirements/delivery-plan.md)。

## 上下文来源优先级

1. 代码与配置（事实）。
2. `docs/` 与 `AGENTS.md` / `CLAUDE.md`（约定）。
3. 任务描述与验收标准。
4. 会话记录（仅辅助）。

冲突时以更高优先级为准，并修正低优先级材料。

## 会话归档

- 使用 `npm run session:save` 记录任务标题、状态与备注。
- 使用 `npm run session:summary` 查看最近记录。
- 长期决策写入 `docs/08-governance/decision-log.md`，不只留在归档。
- 归档存放于 `.ai/`，说明见 `.ai/README.md`。

## 护栏

- 不擅自引入新依赖、新框架或新服务。
- 后端遵守 .NET 10 + EF Core 约定；不引入第二套数据访问方式。
- 鉴权与社交分发为延后能力，不要提前实现（ADR-007、ADR-008）。
- 不修改与任务无关的文件。
- 不删除历史决策；用新记录覆盖结论并注明日期。
- 不在代码、日志或文档中写入密钥与个人敏感信息。
- 发布、数据库破坏性变更、删除数据必须人工确认。

## 多 Agent 切换

- 切换工具时先读 `AGENTS.md` 与 `CLAUDE.md`。
- 保持相同的任务模板、验证门槛与文档更新要求。
- 不依赖某个 Agent 的私有记忆；需要保留的信息写入仓库。
