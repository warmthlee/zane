# ADR-010 · 想法流共享口令

- 日期：2026-11-09
- 状态：已接受
- 关联：ADR-007、PRD-09、delivery-plan-phase3

## 背景

首页需要一个可编辑、可删除的短想法流。用户鉴权仍延后（ADR-007），但写操作不能完全裸露在可访问网络中。完整登录、会话与用户表会显著扩大阶段 3 范围；只靠网络限制又无法覆盖“已经能访问站点的人误改或恶意修改”的情况。

## 决策

Memos 的创建、编辑、删除使用**共享口令**保护，作为用户鉴权落地前的临时写保护：

- 口令由服务端配置 `Memos:Passphrase` 注入，前端通过 `X-Memo-Passphrase` 请求头提交。
- 服务端使用 SHA-256 + `CryptographicOperations.FixedTimeEquals` 比较，不存明文会话。
- `POST /api/v1/memos/unlock` 只校验口令，不建立服务端会话；前端把口令保存在 `sessionStorage`，收到 `401` 时清除。
- 解锁与写操作按来源 IP 限流，默认 5 次 / 5 分钟。
- 写接口仍要求本机/内网或受信网络限制；口令是额外保护，不替代网络限制。
- 口令不提供按用户隔离、审计归属或找回能力；任何持有口令的人可以修改全部想法。

## 备选

| 方案 | 不采用原因 |
| --- | --- |
| 完整用户鉴权 | 超出阶段 3 范围，与 ADR-007 的延后结论冲突 |
| 仅网络限制 | 无法防止已进入网络的误操作或共享设备滥用 |
| 前端本地口令 | 可被绕过，不能保护服务端数据 |
| 每条想法单独密码 | 使用成本高，不符合快速记录目标 |
| 口令 + 服务端 Session | 更接近登录系统，但对单用户站点收益有限，延后到 MEMO-11 一并考虑 |

## 影响

- 生产必须配置 `Memos__Passphrase`；缺失时写接口与 `unlock` 返回 `503`，只允许只读。
- 口令轮换会使所有前端已保存的会话口令失效，需要重新解锁。
- 口令不能写入仓库、日志、URL 或 `localStorage`；前端只保存在 `sessionStorage`。
- 这是临时边界，不是最终权限模型；MEMO-11 落地用户鉴权与想法归属后，应替换共享口令并新增 ADR 标注替代关系。
- 写接口的网络限制仍必须保留，避免口令成为唯一防线。
