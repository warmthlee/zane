# ADR-006 · 发布链路

- 日期：2026-11-07
- 状态：已接受

## 背景

仓库已有 GitHub Actions + 1Panel rsync 的前端发布路径；后端切换为 .NET 10 后需要补充发布方式。

## 决策

- 前端：保留 GitHub Actions 构建 + rsync 到 1Panel 的路径。
- 后端：`dotnet publish -c Release` 产出，部署为 systemd 服务（或 1Panel 进程管理），Nginx 反向代理 `/api`。
- 数据库：SQLite 位于持久化目录，不随发布覆盖；发布前备份。
- 顺序：备份 → 后端（向后兼容）→ 迁移 → 前端 → 健康检查。

## 备选

- 容器化（Docker）：一致性好，但增加镜像与编排维护，暂不采用。
- 单文件发布：可选，但初期不需要。

## 影响

- CI 需要同时安装 Node 与 .NET SDK。
- 需要管理服务进程、环境变量与日志。
- 回滚以产物与数据库备份为单位，不依赖反向迁移。
