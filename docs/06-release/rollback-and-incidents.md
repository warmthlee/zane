# 回滚与事故处理

## 回滚级别

| 级别 | 场景 | 操作 |
| --- | --- | --- |
| L1 前端 | 页面/资源异常 | 重新部署上一份 `dist/` |
| L2 后端 | 接口错误、进程崩溃 | 回退服务进程到上一版本 |
| L3 数据 | 迁移错误、数据损坏 | 停止服务，恢复 SQLite 备份 |
| L4 功能 | 单个功能异常 | 关闭功能开关或隐藏入口 |

按影响面选择最低成本级别，不因小问题做全量回滚。

## 回滚前

- [ ] 确认问题范围与影响用户。
- [ ] 保留现场：日志、请求 ID、错误截图。
- [ ] 确认上一稳定版本与备份时间点。
- [ ] 通知相关方（如适用）。

## 回滚步骤

### 前端

1. 重新构建上一版本，或将上一份 `dist/` 同步到服务器。
2. 验证首页与关键页面。
3. 确认静态资源无 404。

### 后端

1. 停止当前 .NET 进程。
2. 切换到上一版本 `dotnet publish` 产物。
3. 重启 systemd/1Panel 服务。
4. 检查 `/api/v1/health` 与日志。
5. 确认无持续错误。

### 数据

1. 停止服务，禁止写入。
2. 备份当前数据库（保留现场）。
3. 用最近的可用备份替换。
4. 启动服务，验证 EF Core 迁移版本（`__EFMigrationsHistory`）与关键数据。
5. 记录丢失的数据范围。

注意：不依赖 EF Core 迁移反向执行来恢复；破损迁移一律用备份恢复。

## 事故分级

| 级别 | 定义 | 响应 |
| --- | --- | --- |
| P0 | 全站不可用或数据损坏 | 立即处理，优先恢复 |
| P1 | 核心功能不可用（记录/登录） | 尽快处理 |
| P2 | 非核心功能异常（聚合/集成） | 当日处理 |
| P3 | 体验问题 | 排期处理 |

## 事故处理流程

1. 发现与确认：记录时间、现象、影响范围。
2. 止损：回滚、关闭功能或降级。
3. 恢复：验证核心路径。
4. 复盘：写清根因、处理过程、改进项。
5. 跟进：把改进项登记到 backlog 或风险表。


## 预防

- 发布前备份与迁移演练。
- 小步发布，保留上一版本。
- 外部依赖设置超时与降级。
- 关键路径有测试与告警。
- 不把未验证的迁移直接用于生产。
