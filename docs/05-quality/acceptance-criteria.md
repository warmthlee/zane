# 验收标准

## 通用验收

每个任务完成前必须满足：

- [ ] 改动符合任务声明的范围，没有顺手扩张。
- [ ] 前端 `npm run build` 通过。
- [ ] 前端 `npm run lint` 通过。
- [ ] 后端 `dotnet build` 通过（迁移后）。
- [ ] 后端 `dotnet test` 通过（测试接入后）。
- [ ] 新增逻辑有对应测试。
- [ ] 加载、空、错误状态已处理。
- [ ] 相关文档已更新（PRD / 架构 / ADR 至少其一）。
- [ ] 无调试代码、临时日志与敏感信息。

## 模块级验收

阶段 1 的逐步验收、命令与出口门禁见 [`../01-requirements/delivery-plan.md`](../01-requirements/delivery-plan.md)；本文件只定义验收标准，不记录执行步骤。

### 平台基础（PRD-00）

- [ ] `src`、`src-dotnet`、`src/api-client` 可独立构建。
- [ ] 健康接口在数据库可用/不可用时分别返回 200/503。
- [ ] OpenAPI 3.1 文档可访问且包含全部端点。
- [ ] `dotnet ef database update` 可在空库创建结构。
- [ ] 统一错误响应为 ProblemDetails。

### 思想记录（PRD-01）

- [ ] 可创建、编辑、删除记录，刷新后数据不丢失。
- [ ] 关键词与标签可组合筛选。
- [ ] 草稿自动保存生效，离开有提示。
- [ ] 导出 Markdown/JSON 内容完整。
- [ ] 删除操作有二次确认。
- [ ] 写入接口仅本机/内网可达（鉴权落地前）。

### 在线工具（PRD-02）

- [ ] 无需登录即可使用。
- [ ] 输入非法时有明确提示。
- [ ] 结果可复制或下载（适用时）。
- [ ] 纯前端工具不发起上传请求。
- [ ] 移动端可用。

### 创意 MVP（PRD-03）

- [ ] 每个 MVP 有独立入口与说明。
- [ ] MVP 之间互不影响。
- [ ] 可独立下线且不破坏主站。

### 最佳实践 / Cheat Sheet（PRD-04 / PRD-07）

- [ ] 内容结构统一，可检索。
- [ ] 代码块可复制。
- [ ] 与记录共享标签体系（适用时）。

### 热点聚合（PRD-05）

- [ ] 各数据源独立接入，单个失败不影响其他源。
- [ ] 展示来源与更新时间。
- [ ] 失败时展示缓存并标注。
- [ ] 遵守数据源频率限制与条款。
- [ ] 后台任务不阻塞请求线程。

### 第三方集成（PRD-06）

- [ ] 集成页可正常加载。
- [ ] 加载失败时提供外部链接兜底。
- [ ] 明确标注第三方来源。

## 延后能力（当前不验收）

- 用户鉴权（ADR-007）。
- 社交平台一键分发（ADR-008）。

## 发布级验收

- [ ] 需求范围内功能全部通过模块验收。
- [ ] 发布门禁全部通过（前端 build/lint，后端 build/test）。
- [ ] 数据库迁移在副本上演练成功。
- [ ] 备份已完成并验证可恢复。
- [ ] 回滚步骤已确认可执行。
- [ ] 发布后检查清单完成。

## 验收记录

验收结果写入任务记录或 `docs/08-governance/changelog.md`，包含：

- 验收时间与环境。
- 执行的命令与结果。
- 未覆盖项及原因。
- 遗留风险与后续任务。
