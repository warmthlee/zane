# 监控与分析

## 监控目标

- 主站与 API 可用。
- 核心流程（记录保存、工具、后台抓取）无持续错误。
- 外部数据源失败可被发现且有降级。
- 数据安全：备份存在且可恢复。

## 健康检查

`GET /api/v1/health` 返回：

```json
{
  "status": "ok",
  "checks": {
    "database": "ok",
    "uptimeSeconds": 12345,
    "version": "1.0.0"
  }
}
```

数据库不可用时返回 503，并说明失败项。检查使用 `AppDbContext.Database.CanConnectAsync()`，并设置超时。

## 日志与追踪

- .NET 结构化日志：时间、级别、请求 ID、路径、耗时、错误码。
- OpenTelemetry：
  - ASP.NET Core 请求指标与追踪。
  - `HttpClient` 外部调用耗时与失败。
  - EF Core 查询耗时（注意采样，避免噪声）。
- 不记录密码、Token、完整连接字符串与敏感正文。
- 保留至少 14 天；错误日志单独聚合。
- 适配器记录数据源、耗时、结果条数与失败原因。

## 指标

| 指标 | 说明 | 建议告警 |
| --- | --- | --- |
| 可用性 | 首页/健康接口成功率 | 5 分钟失败 ≥ 3 次 |
| API 错误率 | 5xx 占比 | > 1% 持续 10 分钟 |
| 响应时间 | P95 | > 500ms 持续 10 分钟 |
| 外部抓取失败 | 连续失败次数 | 连续 3 次 |
| 磁盘空间 | 数据库与备份分区 | < 20% |
| 备份新鲜度 | 最近备份时间 | > 36 小时 |
| 进程重启 | systemd 重启次数 | 1 小时内 ≥ 2 次 |

阈值是初始建议，运行后按实际调整。

## 访问分析

- 优先使用隐私友好的统计（如自建 Plausible/Umami）。
- 只收集必要指标：页面访问、工具使用次数、来源。
- 不采集与产品无关的个人数据。
- 统计脚本失败不得阻塞页面。

## 工具与 MVP 观察

- 每个工具记录使用次数与错误次数。
- MVP 记录入口点击与完成关键动作的比例。
- 低使用或高错误的 MVP 进入评估：迭代或归档。

## 告警处理

1. 确认影响范围。
2. 查看最近发布、EF Core 迁移与外部依赖状态。
3. 按 `../06-release/rollback-and-incidents.md` 止损。
4. 记录处理过程。
