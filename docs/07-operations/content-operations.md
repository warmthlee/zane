# 内容运营

## 内容类型

| 类型 | 载体 | 生命周期 |
| --- | --- | --- |
| 思想记录 | `notes` | 草稿 → 发布 → 可归档（社交同步延后） |
| 最佳实践 | `patterns` | 草稿 → 发布 → 持续修订 |
| Cheat Sheet | `cheatsheets` | 草稿 → 发布 → 定期校对 |
| MVP 说明 | `mvps` | 实验中 → 上线 → 归档 |

## 写作流程

1. **捕获**：随时记录，不追求完整；保留原始想法。
2. **整理**：补充标题、标签、摘要，拆分过长内容。
3. **校对**：检查事实、代码可运行性、链接有效性。
4. **发布**：设为已发布，进入检索与公开页面。
5. **分发**：选择同步目标，一键发布到社交平台。
6. **回顾**：定期回看，更新过时内容或标记归档。

## 标签体系

- 标签用于跨内容类型检索，避免同义标签。
- 建议维度：主题（前端/设计/工具）、类型（总结/案例/速查）、状态（实验/稳定）。
- 标签数量保持精简，新增前先检索是否已存在。

## 社交分发（延后）

当前不做社交平台自动分发（ADR-008）。先用导出能力完成内容输出，未来启用时遵循：

- 首批只支持一个平台，验证链路后再扩展。
- 发布前检查：标题长度、摘要、链接、话题标签。
- 同步失败保留本地内容，允许重试。
- 记录外部链接，便于回溯。
- 不在自动发布中携带敏感信息。

## 内容质量

- 每篇内容至少包含：问题/动机、正文、结论或下一步。
- 代码示例必须可运行或明确标注伪代码。
- 引用外部内容注明来源。
- 过时内容标注更新时间或归档，不静默删除。

## 归档与清理

- 长期无维护且不再适用的内容标记 `archived`。
- 归档内容保留可访问链接，避免死链。
- 删除仅用于误建或敏感内容，并记录原因。

## 数据备份

- SQLite 每日备份。
- 每月导出一次 Markdown/JSON 快照。
- 备份与导出文件不与生产库混放。
- 定期验证导出内容可读、可导入。
