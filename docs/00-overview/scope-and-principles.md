# 范围与设计原则

## 范围矩阵

| 类别 | 内容 | 处理方式 |
| --- | --- | --- |
| 核心 | 思想记录、标签与检索、Cheat Sheet | 必须做，优先保证稳定 |
| 核心 | 在线工具（二维码、Base64、ASCII 等） | 必须做，保持无登录可用 |
| 延伸 | 创意 MVP（古诗词、英语学习、打字练习） | 逐个孵化，可独立上下线 |
| 延伸 | 最佳实践与设计模式案例 | 随内容积累逐步完善 |
| 延伸 | 热点与股票聚合 | 适配器接入，允许降级 |
| 延伸 | 第三方工具集成（Excalidraw） | 按需嵌入，不改变主站边界 |
| 延后 | 用户鉴权 | ADR-007，落地前写接口仅本机/内网 |
| 延后 | 社交平台一键分发 | ADR-008，先完成记录与导出 |
| 不做 | 多租户、企业权限、审批流 | 明确排除 |
| 不做 | 重型 CMS、复杂内容工作流 | 明确排除 |
| 不做 | 社交关系链、评论区社区 | 明确排除 |

## 设计原则

1. **内容优先**：记录、检索与阅读体验优先于视觉噱头。
2. **工具轻量**：单个工具独立、无状态、打开即用，不强制登录。
3. **MVP 可隔离**：每个创意实验可单独发布和下线，失败不影响主站。
4. **适配器隔离外部依赖**：热点、股票、第三方工具都通过适配器接入，接口变化不外溢。
5. **数据可迁移**：SQLite 文件可备份、可导出，避免不可逆的平台绑定。
6. **单体优先**：一个前端 + 一个 .NET 后端，不提前拆分服务。
7. **契约单一来源**：服务端 OpenAPI 是唯一 API 契约，前端类型由它生成。
8. **渐进增强**：外部数据失败时页面仍可读，使用缓存或空状态。
9. **可验证**：每个功能都有明确验收标准与最小验证方式。
10. **跟随 .NET 10**：优先使用 LTS 提供的现代能力，不引入过时写法。
11. **组件复用优先**：前端 UI 以 shadcn/ui 为唯一组件来源，无特殊情况不重复造轮子。

## 取舍记录

| 取舍 | 选择 | 原因 |
| --- | --- | --- |
| 数据库 | SQLite 而非 PostgreSQL | 单用户、低并发、部署简单、文件可备份 |
| 后端 | .NET 10 而非 Node | 目标调整为 .NET；强类型、内置校验与 OpenAPI |
| 数据访问 | EF Core 10 而非 Dapper/裸 SQL | 迁移、映射与类型安全，维护成本低 |
| 状态管理 | Redux Toolkit 而非仅局部状态 | 跨页面共享筛选、草稿与请求缓存 |
| 样式与组件 | Tailwind + shadcn/ui | 保留设计自由度；组件源码入库，避免重型运行时依赖 |
| 架构 | 前后端分离但同仓 | 边界清晰，部署仍可控 |
| 契约 | OpenAPI 生成客户端 | .NET 与 TS 无法共享运行时类型，生成可避免漂移 |
| 内容存储 | 结构化数据而非纯 Markdown 文件 | 支持检索、标签关系与状态 |

架构决策的完整记录见 `../08-governance/adr/`。
