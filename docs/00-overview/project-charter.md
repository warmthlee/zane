# 项目章程

## 一句话定义

一个用于总结经验、记录想法的个人网站，也是一个孵化产品 MVP 的游乐场。

## 背景与问题

个人知识、经验和灵感散落在笔记软件、聊天记录与零散代码中，难以复用；同时很多产品想法缺少低成本验证场所。项目要同时解决两件事：

1. 建立可持续的个人知识与思想沉淀体系。
2. 提供低成本的工具与 MVP 试验场，快速验证想法。

## 愿景

成为作者长期使用的“个人工作台”：记录、检索、复用、分发在同一处完成，并能持续孵化小产品。

## 目标

- 能持续记录思想、总结与最佳实践，并支持全文检索。
- 内容可导出；一键分发到社交平台作为未来能力，不进入当前阶段。
- 提供一批高频在线工具，打开即用、无需登录。
- 每个创意 MVP 可独立发布、独立下线，不影响主站。
- 聚合热点与行情信息，形成每日信息入口。
- 集成外部工具（如 Excalidraw），减少工具切换。
- 提供可复用的 Cheat Sheet。

## 非目标

- 不做多租户 SaaS 或面向企业的权限、审批体系。
- 不做重型 CMS、复杂工作流引擎。
- 不追求社交关系链、评论社区等重运营功能。
- 不在早期引入微服务、消息队列等超出规模的架构。

## 目标用户

- 主要用户：作者本人（内容生产、工具使用、MVP 验证）。
- 次要用户：公开访问的读者与工具使用者。

## 成功指标

| 维度 | 指标 | 目标 |
| --- | --- | --- |
| 内容 | 每周新增有效记录 | ≥ 3 条 |
| 复用 | 笔记被再次检索/引用 | 每月 ≥ 10 次 |
| 分发（延后） | 一键同步成功率 | ≥ 95% |
| 工具 | 常用工具可用性 | ≥ 99% |
| 孵化 | 每年完成 MVP | ≥ 2 个 |
| 维护 | 主站构建与发布 | 可重复、可回滚 |

指标用于判断方向，不作为早期硬性 KPI。

## 关键约束

- 个人项目，维护成本必须低。
- 技术栈统一为 React + TypeScript + Vite + Redux Toolkit + Tailwind + shadcn/ui；后端 .NET 10 + EF Core 10 + SQLite。
- 数据必须可导出、可备份，避免平台锁定。
- 外部数据源不稳定，必须允许失败与降级。
- AI 可以加速实现，但产品判断与发布确认由人负责。
