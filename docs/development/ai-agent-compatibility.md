# AI Agent 兼容性设计

## 目标

本项目的目标不是绑定某一种 AI 编程工具，而是让它们都能在相同的工程契约下工作。

## 设计原则

1. 命令与脚本统一：所有 Agent 都应使用相同的 `npm` 执行入口。
2. 文档对外一致：README、AGENTS.md、docs 下的流程说明应保持一致。
3. 任务输入标准化：需求、范围、验收标准和验证方式是固定结构。
4. 输出可审计：每个任务都应保留更改说明、验证记录和风险说明。

## 工作流约定

### 通用执行链

```bash
npm install
npm run dev -- --host 0.0.0.0
npm run build
npm run lint
```

### 每个任务都必须明确以下内容

- 目标：做什么
- 不做：不做什么
- 方案：如何实现
- 验收：如何确认完成
- 风险：可能产生的副作用

## Agent 兼容建议

- 使用仓库内定义的脚本，而不是依赖工具私有命令。
- 将设计说明写入 `docs/`，避免“只在 chat 中存在”的上下文。
- 把环境变量、构建命令和发布规则固定下来，避免工具切换引发工作流断裂。
- 在多 Agent 切换时，保留一致的任务模板，确保相同需求得到相同质量门槛。

## 验收结果

已实现的关键点：
- 根目录提供 `AGENTS.md`，作为 Agent 统一入口。
- README 明确说明开发与发布入口。
- 设计规范写入 docs，确保 AI 工作模式具备持久化知识基础。
