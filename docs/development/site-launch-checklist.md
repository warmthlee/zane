# 上线检查清单

## 1. 发布前检查

### 1.1 代码与构建
- [ ] `npm install` 已执行
- [ ] `npm run build` 已通过
- [ ] `npm run lint` 已通过
- [ ] `npm run release:check` 已通过
- [ ] `dist/` 产物已生成并可检查

### 1.2 仓库状态
- [ ] 当前分支是预期发布分支
- [ ] 代码已提交且无未跟踪的关键变更
- [ ] 变更摘要已记录在文档或任务说明中
- [ ] 发布范围已明确，任何风险项已列出

### 1.3 GitHub Pages 准备
- [ ] GitHub 仓库已连接到 GitHub Pages
- [ ] GitHub Pages 的 Source 已设为 `Deploy from a branch` 或匹配的受支持方案
- [ ] 目标分支为 `gh-pages`
- [ ] 仓库中的 `gh-pages` 分支已存在
- [ ] 站点域名或自定义域名（如有）已确认

## 2. 发布执行

### 执行命令

```bash
npm run release:deploy
```

### 发布后检查
- [ ] 站点首页能正常访问
- [ ] 页面样式和资源加载正常
- [ ] 路由回退和静态资源无 404
- [ ] 最新变更已反映到 Pages 产物中
- [ ] `.ai/releases/latest-deploy.json` 已生成并记录成功状态

## 3. 发布后确认

- [ ] 站点打开速度和资源加载无明显异常
- [ ] 关键页面（首页、归档页、作者页、关于页）渲染成功
- [ ] 排版、深浅色主题、交互正常
- [ ] 需要记录的风险和回滚步骤已经更新到文档

## 4. 回滚准备

在发现问题后，执行：

```bash
npm run release:rollback
```

并确认：
- [ ] 备份或历史成功版本已标识
- [ ] 恢复步骤清晰且可执行
- [ ] 相关问题已记录为下一次修复的输入

## 5. 实际操作提示

当前仓库已具备 GitHub Pages 的自动部署脚本和产物归档。最后一步需要在 GitHub 仓库设置中确认 `Settings -> Pages` 已开启，并确保 `Source` 指向 `gh-pages` 分支。

如果 GitHub 仓库设置页未开启，则站点虽然脚本可执行，但对外访问仍不会生效。
