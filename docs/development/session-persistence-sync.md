# 会话保存与多端同步设计

## 目标

AI 编程不应只存在于一次即时对话中，而应当形成可恢复、可归档、可同步的任务履历。

## 方案

### 1. 代码与文档作为主仓库状态

仓库中的代码、README、docs、AGENTS.md 是项目的主状态。所有 AI 任务都应以此为基础，不把聊天记录作为唯一事实来源。

### 2. 会话归档采用结构化记录

建议保留以下内容：
- 任务名称
- 范围（in scope / out of scope）
- 关键决策
- 代码变更摘要
- 验收结果
- 发布/回滚备注

本仓库已增加 `.ai/session-state-template.json` 作为标准模板，并提供脚本：

```bash
npm run session:save -- "Task title" "in_progress" "Notes"
npm run session:summary
```

当前实现采用 SQLite 作为正式归档存储，路径为 `.ai/session-archive.db`，同时导出 JSON 格式的快照到 `.ai/session-archive.json` 以方便检查和迁移。`session:summary` 可快速查看最近的历史。

### 3. 多端同步方式

适用于未来的多终端团队或个人工作流：
- 本地 Git 提供代码基础存储
- 结构化任务记录提供上下文备份
- 云端或共享存储提供同步入口
- 关键产物（文档、发布记录、验收清单）可通过统一目录同步

### 4. 关键原则

- 不依赖单一 AI 工具提供全部记忆
- 所有任务需可从仓库与归档材料中恢复
- 需要保存“为什么做这个”以及“如何验证”，而不是只保存最终结果

## 该阶段的现实状态

当前博客是一个静态前端项目，适合先采用“仓库 + 文档 + 结构化会话模板”的持久化方式，而不是一上来引入重型后端数据库方案。这样更符合当下项目规模和 AI 协作需求。
