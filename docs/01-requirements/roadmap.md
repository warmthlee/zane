## 阶段 1：平台迁移与记录能力（进行中）

**目标**：迁移到目标结构，打通“写—存—查”。

执行步骤、分步验收与出口门禁见 [`delivery-plan.md`](delivery-plan.md)。步骤 S0–S5 已完成，`NOTE-01`～`NOTE-03` 的记录 CRUD 尚未开始。

首页、想法流与全局入口的迭代见 [`delivery-plan-phase3.md`](delivery-plan-phase3.md)。其中 `memos` 是首页短想法，与 `NOTE-01` 的长文记录是两套独立模型；想法流的需求见 [PRD-09](prd/prd-09-memos.md)。

- 前端统一在 `src/`；建立 `src-dotnet/` 与 `src/api-client/`。
- .NET 10 API + EF Core 10 + SQLite 迁移。
- 实现记录 CRUD、标签、检索与导出。
- OpenAPI 生成前端客户端。
- 建立构建、测试与发布门禁。

**不包含**：用户鉴权（ADR-007）、社交分发（ADR-008）。

**退出条件**：可稳定创建、检索、编辑记录；数据可备份。

## 阶段 2：在线工具与 Cheat Sheet

- 工具列表与统一布局。
- 二维码、Base64、ASCII 码表。
- Cheat Sheet 列表、搜索与复制。

**退出条件**：首批工具无需登录可用，且纯前端工具不依赖后端。

## 阶段 3：最佳实践与内容输出

- 最佳实践内容模型与展示。
- 记录导出与内容复用。
- 为未来的社交分发预留适配器边界（不实现）。

**退出条件**：内容结构统一、可检索、可导出。

## 阶段 4：聚合与集成

- 数据源适配器框架（基于 `HttpClient` + `HybridCache` + 后台任务）。
- 百度、微博头条接入。
- 股票信息与自选。
- Excalidraw 集成与兜底。

**退出条件**：外部源失败时主站仍可用，缓存与时间戳可展示。

## 阶段 5：MVP 孵化

- MVP 注册、上下线机制。
- 古诗词、英语学习、打字练习等候选。
- 每个 MVP 独立验收、独立回滚。

**退出条件**：至少一个 MVP 上线并可独立下线。

## 阶段 6：账号与分发（延后）

- 用户鉴权（ADR-007）。
- 社交平台同步适配器（ADR-008）。
- 多平台分发与失败重试。

**进入条件**：内容与记录能力稳定，且明确需要公网写入。

## 优先级原则

1. 先保证记录与检索可用，再做分发与聚合。
2. 外部依赖最后接入，避免早期被不稳定数据源拖住。
3. 每个阶段都必须可发布、可回滚，不攒大版本。
4. 未完成当前阶段退出条件，不提前开启下一阶段的主要功能。
