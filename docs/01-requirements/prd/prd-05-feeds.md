# PRD-05 · 热点聚合

- 状态：planned
- 阶段：阶段 4

## 背景与目标

聚合百度头条、微博头条与股票信息，形成每日信息入口。外部数据不稳定，必须先保证降级与缓存。

## 用户故事

- 作为作者，我可以在一处查看多个来源的热点。
- 作为作者，我可以看到数据来源与更新时间。
- 作为作者，外部源失败时仍能看到上次缓存。

## 功能要求

| 编号 | 要求 | 优先级 |
| --- | --- | --- |
| FEED-01 | 数据源适配器框架 | P1 |
| FEED-02 | 百度头条接入 | P1 |
| FEED-03 | 微博头条接入 | P1 |
| FEED-04 | 定时抓取与缓存 | P1 |
| FEED-05 | 失败时展示缓存与时间戳 | P1 |
| FEED-06 | 股票信息与自选列表 | P2 |
| FEED-07 | 来源与更新时间标注 | P1 |

## 适配器契约

每个适配器实现统一接口：

- `FetchAsync`：拉取并归一化。
- 超时与重试上限。
- 返回条目：外部 ID、标题、链接、来源、时间。
- 失败时抛出可识别异常，由上层记录并保留缓存。

## 约束

- 遵守数据源条款与频率限制。
- 不绕过访问控制。
- 单个源失败不影响其他源与主站。
- 抓取任务不得与请求线程耦合，避免页面被拖慢。

## 验收标准

- [ ] 每个源可独立启用/停用。
- [ ] 源失败时页面展示缓存与时间。
- [ ] 条目去重（`source_id + external_id`）。
- [ ] 抓取日志包含耗时与结果数量。
