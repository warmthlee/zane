# PRD-03 · 创意 MVP 游乐场

- 状态：planned
- 阶段：阶段 5

## 背景与目标

以最低成本验证产品想法。每个 MVP 独立开发、独立上线、独立归档，失败不影响主站。

## 用户故事

- 作为作者，我可以快速上线一个 MVP 实验。
- 作为作者，我可以下线或归档不再维护的 MVP。
- 作为访客，我可以清楚看到每个实验的状态与说明。

## 功能要求

| 编号 | 要求 | 优先级 |
| --- | --- | --- |
| MVP-01 | MVP 注册表：名称、slug、状态、入口 | P1 |
| MVP-02 | 状态：实验中 / 已上线 / 已归档 | P1 |
| MVP-03 | 独立路由与错误边界 | P1 |
| MVP-04 | 独立上下线，不影响其他模块 | P1 |
| MVP-05 | 古诗词 | P2 |
| MVP-06 | 英语学习 | P2 |
| MVP-07 | 打字练习 | P2 |

## 约束

- MVP 优先复用已有内容与工具能力。
- 单个 MVP 的依赖不得污染主站构建。
- 归档后保留说明页与数据导出，避免死链。

## 验收标准

- [ ] 下线任一 MVP 不需要改动其他模块。
- [ ] MVP 入口可单独隐藏。
- [ ] 每个 MVP 有独立验收记录。

## 开放问题

- MVP 使用主域子路径还是独立子域名？初期建议子路径，降低部署成本。
