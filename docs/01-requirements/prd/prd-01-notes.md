# PRD-01 · 文章与长文记录

- 状态：planned
- 阶段：阶段 1（记录 CRUD/检索）；阶段 3 补充静态文章渲染；社交分发延后
- 关联：PRD-00、PRD-09、ADR-008

## 背景与目标

沉淀个人思想、技术总结与灵感。核心是“写得快、找得到、不丢失”。本 PRD 的 `notes` 面向长文/文章：有标题、Markdown 正文、状态与标签。首页短想法由 [PRD-09](prd-09-memos.md) 的 `memos` 承载，两者数据模型、编辑流程与接口独立，不合并。

阶段 3 先完成静态 Markdown 文章的完整渲染与首页精简文章列表；文章元数据仍暂存在前端 `data.ts`，迁移到 frontmatter 作为后续任务（NOTE-14）。社交平台一键分发作为未来能力，当前不进入实现范围。

## 用户故事

- 作为作者，我可以创建、编辑、删除记录。
- 作为作者，我可以用标签组织内容，并按关键词检索。
- 作为作者，我可以区分草稿与已发布内容。
- 作为作者，我可以导出记录，避免数据锁定。
- （未来）作为作者，我可以把记录一键同步到社交平台。

## 数据与接口

- 表：`notes`、`tags`、`note_tags`。
- 接口：`GET/POST /api/v1/notes`、`GET/PATCH/DELETE /api/v1/notes/{id}`。
- 检索初期使用 SQLite FTS5 或 `LIKE` + 索引；优先保证正确性。

### 阶段 3 静态文章

- 正文继续存放在 `src/features/notes/content/posts/*.md`，用 Vite `import.meta.glob` 收集。
- 渲染使用 `react-markdown` + `remark-gfm`；保留目录、标题锚点与代码复制。
- 文章元数据（标题、日期、分类、摘要、标签、阅读时长）阶段 3 仍暂存在 `src/features/notes/data.ts`。
- 元数据迁移到 frontmatter 是 NOTE-14，阶段 3 不执行。
- 首页只展示 5 条紧凑文章行；完整列表仍在 `/notes`。

## 验收标准

- [ ] 刷新页面后记录不丢失。
- [ ] 关键词与标签可组合筛选，结果正确。
- [ ] 草稿自动保存生效。
- [ ] 导出内容完整可读。
- [ ] 删除操作有二次确认。
- [ ] 静态文章完整渲染 Markdown，目录锚点与代码复制可用。
- [ ] 原始 HTML 不被执行。

## 开放问题

- 记录正文是否保留历史版本？初期建议只保留 `updated_at`，版本历史延后。
- 公开阅读与私有记录的边界如何划分？鉴权延后期间建议写接口仅在本机/内网开放。
