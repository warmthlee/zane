## 部署前的 checklist

在项目进入部署前，我会先检查三件事：环境变量是否齐全、路由是否兼容静态托管、构建产物是否有未使用的依赖或大体积资源。

这类问题看起来琐碎，但一旦忽略，很容易在上线后出现空白页、资源404或构建结果不符合预期。

- 检查 base / publicPath
- 确认环境变量命名
- 确认路由 fallback

## 最常用的命令

Vite 的开发体验确实很好，但脚本和环境变量的约定要提前统一，否则后面很难维护。通常我会把 build、preview 和 lint 这些动作放进统一脚本里，减少每次发布时的“记忆负担”。

```bash
npm run build
npm run preview

# 生产环境变量示例
VITE_API_BASE_URL=https://api.example.com
```

## 上线后验证

部署并不代表结束。真正可靠的上线流程，通常还包括：回归页面访问、检查 API 地址、看看图片和字体资源是否命中正确路径。

如果项目使用的是静态托管服务，那么路由回退和缓存策略就更值得提前验证。
